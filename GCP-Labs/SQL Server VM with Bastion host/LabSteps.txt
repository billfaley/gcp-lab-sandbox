Challenge scenario
Your company has decided to deploy new application services in the cloud and your assignment is developing a secure framework for managing the Windows services that will be deployed. You will need to create a new VPC network environment for the secure production Windows servers.

Production servers must initially be completely isolated from external networks and cannot be directly accessed from, or be able to connect directly to, the internet. In order to configure and manage your first server (SQL Server) in this environment, you will also need to deploy a bastion host, or jump box, that can be accessed from the internet using the Microsoft Remote Desktop Protocol (RDP). The bastion host should only be accessible via RDP from the internet, and should only be able to communicate with the other compute instances inside the VPC network using RDP.

Your company also has a monitoring system running from the default VPC network, so all compute instances must have a second network interface with an internal only connection to the default VPC network.

From Gemini:
    Configuring a Firewall Rule in GCP to Allow Inbound RDP Traffic

    To configure a firewall rule in GCP to allow inbound RDP traffic (TCP port 3389) from the internet to a bastion host using network tags, follow these steps:

    Before you can attach a tag, you need to create a tag and configure its value. 
    To create tag keys and tag values, see Creating a tag and Adding a tag value.


    1. Create a Network Tag Key:

    Navigate to the Network Tags page in the Google Cloud Console (under IAM).
    Click Create Network Tag Key.
    Give the tag a name, such as bastion-host.
    Click "For use with network firewall"
        -> Choose project and network
    
    Click "Create Tag Key"

    2. Create tag value (still within IAM\Tags)




    2. Assign the Network Tag to the Bastion Host:
    Navigate to the Compute Engine page.
    Select the bastion host instance.
    In the Network Interfaces section, add the bastion-host network tag to the instance.
    3. Create a Firewall Rule:

    Navigate to the Firewall page.
    Click Create Firewall Rule.
    Give the rule a name, such as Allow RDP to Bastion Host.
    Source IP Ranges: Set this to 0.0.0.0/0 to allow traffic from any IP address.
    Target Tags: Select the bastion-host network tag.
    Specified Protocols and Ports: Add a rule for tcp:3389 to allow RDP traffic.
    Action: Set this to Allow.
    Priority: Set a priority for the rule. A lower priority number indicates a higher priority.
    Additional Considerations:

    Security Best Practices:
    Consider using a more restrictive source IP range if possible, such as allowing traffic only from specific IP addresses or networks.
    Implement strong password policies and multi-factor authentication for the bastion host.
    Regularly patch and update the bastion host to address security vulnerabilities.
    Monitor network traffic to the bastion host for unusual activity.
    Bastion Host Configuration:
    Ensure the bastion host is configured to allow RDP traffic.
    Consider using a bastion host solution that provides additional security features, such as session recording and timeouts.
    Network Segmentation:
    If possible, consider using network segmentation to isolate the bastion host from other sensitive resources. This can help limit the potential impact of a security breach.
    By following these steps and considering the additional security best practices, you can effectively configure a firewall rule in GCP to allow inbound RDP traffic to your bastion host while minimizing security risks.

Simpler Task - Create a SQL Server with a hostname, network tag, 

1. Create VM
    - sql-vm3
2. Choose image (e.g. SQL Server for Windows)
3. Go to Advanced Options\networks
    - Add network tag (e.g. sql-svr)
    - Create hostname: sql-vm3.bf-sandbox.b5678
4. Click "Create VM"
5. Navigate to VM in Google Cloud Console
    - Click 'Set Windows password'
    - Accept username (username you are logged into GCP as)
6. Download RDP file
7. Open RDP with Microsoft Remote Desktop program
8. Login to VM
9. Note - as of this writing, opening the SQL Server Management Studio the first time, you'll try to choose Windows Login, but it won't work.
    !!! WORKAROUND !!!!
    Try connecting to the SQL Server instance using the sqlcmd utility from the command line. Open a command prompt as the local administrator and run:
    
    sqlcmd -E
    
    If you can connect successfully, you can add your user to the SQL Server sysadmin role with:

    CREATE LOGIN [DOMAIN\YourUsername] FROM WINDOWS;
    ALTER SERVER ROLE [sysadmin] ADD MEMBER [DOMAIN\YourUsername];
    GO
    EXIT

    Attempt to login again to SSMS
